You're taking over **audio-performance-generator**, an audio-drama generator.

- **The code.** It's at `CommitedBit/audio-performance-generator` on GitHub,
  branch `main`. The latest release is the newest versioned section of

## Rules

- **Never force-push.** Bring `main` into your branch with a merge, not a
  rebase. One concern per PR, each branched from `main`.
- **Never do the owner's jobs.** That means merging, enabling auto-merge,
  running `scripts/bump_version.py`, tagging, publishing releases, or
  changing repository settings or branch protection. `main` is protected, but
  it requires no approvals, so this rule is what keeps merging with the owner.
- **Test first wherever behaviour changes.** Watch the test fail, then fix.
  Mutation-check every fix: re-break it in a scratch copy, confirm the test
  fails, and never commit the re-broken code. A docs-only or lock-only PR
  names the check that proves it instead.
- **CI must pass on all five jobs:** `backend`, `frontend`, `deps`, `e2e` and
  `compose`.
- **Record every behaviour change** with a line under `## [Unreleased]` in
  `CHANGELOG.md`. Each PR fills in the template's "Not verified" section.
- **Keep CLAUDE.md's invariants.** These are the per-image dependency sets,
  the cu128 pins, the non-blocking idle sweep, stubs only with `DEV_STUB`,
  no automatic cloud fallback, and `/health` vs `/health/ready`. If one
  blocks you, explain why in the PR.
- **After changing a pin or a provider's call into a model library**
  (ACE-Step, Stable Audio 3, Chatterbox, diffusers), run
  `python3 scripts/snapshot_contracts.py`.
- **Attribution.** Ignore CLAUDE.md's `Co-Authored-By: Claude …` and
  "Generated with Claude Code" lines. Attribute your commits and PRs as
  Codex, or not at all.

## Step 1: review only (no code changes)

Review in this order. File paths are under `backend/app/` and
`frontend/src/` unless written in full.

1. **The playback engine (#12):** `engine/AudioEngine.ts`,
   `engine/schedule.ts`, `components/Timeline.tsx`, `lib/trim.ts` and
   `hooks/useIndexedAudio.ts`. It is tested only against a fake
   `AudioContext`. Check:
   - the scheduling and fade maths against the Web Audio spec
   - the IndexedDB → server re-fetch fallback (`loadClipAudio`)
2. **The contract-test machinery (#10):** `scripts/snapshot_contracts.py`,
   `backend/tests/test_contracts.py` and `backend/tests/contracts/`. Look for
   ways it gives false confidence.
3. **Concurrency:**
   - `providers/base.py`: `_load_lock`, `load`, `in_use`, and the
     non-blocking `unload_if_idle`
   - `_sweep_idle_models` in `main.py`, run via `asyncio.to_thread`
   - `Registry.sweep_idle` in `registry.py`
   - `rng.py`, `gpu_lock.py`, `jobs.py`
   - the shared pipeline and per-checkpoint build locks in
     `providers/stable_audio.py`
4. **The gateway** (`gateway.py`, `health.py`): readiness, the discovery
   cache, and routing while upstreams restart.
5. **Security:**
   - `auth.py`, including `OPEN_PATHS`
   - `storage.py`'s `_safe`
   - the voice-upload handlers in `main.py` and `gateway.py`
   - CORS: the `CORS_ORIGINS` default in `config.py`, and the
     `CORSMiddleware` setup in `main.py` and `gateway.py`
   - `frontend/nginx.conf`, which must never inject the API key
   - the ElevenLabs key staying server-side (`providers/elevenlabs.py`)
   - the loopback port bindings (`BIND_ADDR`) in `docker-compose.yml` and
     `compose.gpu.yml`, and that the `compose.gpu.split.yml` overlay
     publishes no ports of its own

**Reporting.** Give each finding a severity:
- **high:** data loss, a security hole, or wrong audio or timing that users
  will hit
- **medium:** a wrong result in an edge case, or false confidence from a test
- **low:** everything else

A defect is **confirmed** only when you have a failing test or an input that
reproduces it; label anything else **suspected**. Give every finding its
`file:line`, its evidence and a suggested fix.

Post the whole review as your reply. Open one issue per confirmed defect,
using the bug template, label `bug`. **Then stop and wait for the owner**
before Step 2.

## Step 2: foundation work that needs no GPU

Keep at most one PR open at a time, in this order. Start the next only after
the owner merges the last one. Every PR adds a CHANGELOG line, so parallel
PRs would conflict.

1. **Job records that survive a restart.** The queue in `jobs.py` is in
   memory only, and it stores a callable for each job, so jobs can't resume.
   - Persist each job's public record (status, result, `audio_id`) per
     service, on the data volume.
   - On startup, mark jobs that were queued or running as failed, with
     "interrupted by restart".
   - Keep `/health`'s `jobs.tracked` counting only this process's jobs.
     `scripts/smoke_gpu.py --idle-check` depends on that, so add a test
     for it.
2. **Opt-in retention for generated audio.** Today `storage.py` has only a
   manual `delete_audio`.
   - Add a setting that is off by default, for example
     `AUDIO_RETENTION_DAYS=0` meaning keep forever.
   - Delete only from `audio_dir`: never voice references, and never the
     audio of a job that is queued or running.
   - Clips in browsers still reference server audio by `audioId`, so
     document the trade-off.
   - Mirror the setting in `.env.example`, the compose files and the README
     config table, with a test in `tests/test_config_defaults.py`.
3. **A lock for the backend's base and dev dependencies only.**
   - Leave out the `tts`, `sfx` and `flash` extras. Their model pins conflict,
     and a plain `uv lock` would try to resolve them. Use, for example,
     `uv pip compile pyproject.toml --extra dev`, or `uv lock` with those
     extras declared as conflicts.
   - Use the lock in `scripts/bootstrap.sh` and CI's `backend` job, not in
     the GPU images.
   - Don't change any model pin, whether in the pyproject extras, the compose
     `MODELS` lines or `requirements-models*.txt`.
     `tests/test_contracts.py` checks that these agree.
4. **Frontend types from the gateway's OpenAPI schema**
   (`app.gateway.app.openapi()`). Do this after item 1, which changes the job
   shape.
   - First add Pydantic response models for the routes
     `frontend/src/api/client.ts` uses, with tests proving no field is
     dropped.
   - Commit the schema JSON. A backend test fails if the schema drifts, and
     the frontend job fails if the generated types drift. CI's `frontend`
     job has no Python.
5. **Structured logging:** an opt-in `LOG_FORMAT=json` in `main.py` and
   `gateway.py`.
   - The default text format stays unchanged.
   - Mirror the setting in `.env.example`, compose and the README.

**A Step 2 item is done** when its PR passes CI, has its CHANGELOG line, a
mutation-checked test where behaviour changed, and a filled-in "Not
verified" section, and the owner has merged it.

**After Step 2, stop and report.**

## Milestones ahead

Details are in HANDOFF.md and docs/plan.md. Don't start any of these without
the owner's go-ahead.

- **M2: the first GPU run (owner only).**
  - The owner runs `python3 scripts/smoke_gpu.py` on the VM, or from the Mac
    with `DOCKER_CONTEXT=gpu`.
  - Then a second pass on the same topology (add `--split` if the first run
    used it):
    `MODEL_IDLE_TIMEOUT=60 python3 scripts/smoke_gpu.py --no-build --quick --idle-check`.
  - The results land in `smoke-results/<timestamp>/results.json`: first,
    warm and cold timings, and VRAM peaks. They gate all GPU-dependent work,
    and may force the split topology (`--split`).
  - The owner will post `report.txt` and `results.json` in a GitHub issue
    titled "M2 results", using the "M2 GPU results" issue template. M3 starts
    only from that issue.
- **M3: hardware tuning.**
  - Ollama as a CPU-only `llm` compose profile, hidden from the GPU.
  - A VRAM budget from M2's numbers.
  - VRAM-aware eviction, only if bigger checkpoints are wanted.
  - An optional RAM parking tier.
  - ACE-Step offload flags as environment variables.
  - Step-level progress from inside model runs.
- **M4: the LLM "director",** as its own service. It turns a story into a
  script, casts it, renders it and puts it on the timeline, using Ollama's
  structured output.
- **M5: finish the loop.** Mixdown and export, server-side projects, and
  undo/redo.
- **v1.0.0** comes only once the GPU path is proven on the hardware and the
  API is meant to be stable. Until then, releases stay 0.y.z, and the owner
  cuts them.

**Begin with Step 0, then Step 1.**
