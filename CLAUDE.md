# CLAUDE.md

Audio-drama generator: a React timeline that places voice, music and sfx clips
generated by local models on an RTX 5090 (Blackwell, sm_120) in a Proxmox VM.
README.md covers deployment and configuration. This file is the map and the
rules for changing the code safely.

## Architecture

```
browser ─ nginx (frontend/) ─/api→ gateway (app.gateway) ─→ model services (app.main)
                                        │                       └ providers: chatterbox, acestep,
                                        │                         stable-audio-3-{sfx,music}, musicgen,
                                        │                         elevenlabs-{voice,sfx}, stub-* (DEV_STUB)
                                        └─ shared data volume: audio + voice references
```

- `backend/app/main.py`: a model service. Routes go to `registry.resolve`, then
  `JobQueue.submit`, which runs `_run_generation` on a thread.
- `backend/app/gateway.py`: merges every upstream's `/v1/models` (cached for
  `MODELS_CACHE_SECONDS`) and routes each request to the owning service. It
  prefixes job ids `service:id` and serves audio straight off the shared volume.
- `backend/app/providers/base.py`: the `Provider` lifecycle
  (`load`/`in_use`/`unload_if_idle`), WAV helpers, `check_audio_sane`.
- `backend/app/health.py`: per-capability status. Only a local model counts as
  `ok`; `cloud`, `stub` and `down` are the others.
- `frontend/src`: `api/client.ts` (API, polling, cancel), `store/` (zustand
  project), `components/Timeline.tsx`, `engine/` (playback scheduling),
  `lib/trim.ts`.

## Invariants: don't break these, and know why they exist

- **Three dependency sets.** Chatterbox, ACE-Step and Stable Audio 3 pin
  mutually incompatible torch and transformers versions. Each image installs
  its model packages `--no-deps` against its own `requirements-models*.txt`,
  with `TORCH_PIN` applied as a uv *override*. Merely installing torch first
  gets downgraded straight back.
- **Blackwell:** CUDA ≥ 12.8 and cu128 wheels; older ones have no sm_120
  kernels. The Dockerfile defaults match compose. `scripts/check_deps.py`
  enforces both.
- **`Provider._load_lock`** is held for the whole multi-minute `_load()`.
  `unload_if_idle` must acquire it non-blocking, and the sweep runs in
  `asyncio.to_thread`. A blocking sweep froze the entire API during model
  loads.
- **`rng_scope`**: a seeded generation holds PyTorch's global RNG exclusively.
  **`gpu_slot`**: flock slots shared across containers (`GPU_LOCK_FILE`).
  Remote (cloud) jobs skip both and run in their own lane.
- **Stable Audio 3** shares one refcounted pipeline per checkpoint, with a
  call lock per pipeline and a build lock per checkpoint. `_SHARED_LOCK` guards
  bookkeeping only; never hold it across a build.
- **Fail loudly.** Stubs exist only with `DEV_STUB=1`. Cloud providers are
  never an automatic default (`ALLOW_CLOUD_DEFAULT=0`). Silent or constant WAVs
  fail the job.
- **`/health` is liveness** and always returns 200. **`/health/ready`** returns
  503 until every `REQUIRED_PROVIDERS` entry can generate. Never use
  `/health/ready` as a container healthcheck.
- **Model-library calls** must match the pinned sources.
  `backend/tests/contracts/*.json` are snapshots of those sources; regenerate
  them with `scripts/snapshot_contracts.py` whenever a pin changes, and keep the
  pins identical everywhere (`test_contracts.py` checks this).
- **Defaults** shared by code, compose, `.env.example`, nginx and Vite must
  agree (`tests/test_config_defaults.py`).

## Checks: run all that apply before every push

```bash
cd backend && .venv/bin/python -m pytest -q && .venv/bin/ruff check app tests   # 140 tests, no GPU or torch
cd frontend && npm run lint && npm run build && npm test                        # vitest
python3 scripts/check_deps.py            # every GPU image's deps resolve, wheel-only (network)
python3 scripts/snapshot_contracts.py --check   # contract snapshots match the pinned sources (network)
python3 scripts/smoke_gpu.py --dev --quick      # dev stack end to end (Docker); then: docker compose -f docker-compose.yml down
docker compose -f compose.gpu.yml -f compose.gpu.split.yml config -q            # also docker-compose.yml and compose.gpu.yml alone
```

On the GPU VM, `python3 scripts/smoke_gpu.py` is the real test. CI
(`.github/workflows/ci.yml`) runs everything above except the snapshot check
and the GPU run.

## How to change things

- **Reproduce first.** Write the test, watch it fail on the unfixed code, then
  fix it.
- **Mutation-check every fix.** Re-break it in a scratch copy and confirm a
  test fails. A test that still passes guards nothing.
- **Never force-push.** Work lands as stacked PRs, each targeting the branch
  below it, merged bottom-up with merge commits.
- **Commit messages** end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; PR bodies end
  with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Traps that cost time before

- **zsh does not word-split** `$VAR`: run loops and multi-argument commands
  under `bash -c`, or use arrays.
- **`TestClient` runs the app lifespan only inside `with`.** Without it, jobs
  never run.
- **`Settings()` creates `DATA_DIR` on import** and is `lru_cache`d.
  `tests/conftest.py` sets the environment and resets settings, the registry
  and the job queue per test.
- **`curl localhost` inside a container can resolve to `::1`** while uvicorn
  listens on IPv4. Use `127.0.0.1`.
- **Keep evidence out of `/tmp`.** It disappears, and so does the proof.
- **A file list without a trailing newline** loses its last line in
  `while read` loops.
